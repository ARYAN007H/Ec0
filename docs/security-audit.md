# ec0 security audit — walled-garden hardening (feat/walled-garden-hardening)

Scope: every network-reachable surface of the ec0 engine (desktop `:core` JVM engine +
Android companion), with emphasis on the recently merged remote-input, VFS, desktop
notification relay, media control, unpair, Quick Settings tiles and daemon-IPC surfaces.
Method: full read of the auth core (handshake, AEAD, envelope signing/verification,
replay window, pin store), then per-service receive-path analysis, then Android
manifest/component review and local secrets hygiene.

Severity model: CRITICAL = remotely exploitable by an unauthenticated peer; HIGH =
exploitable by a network peer or a compromised-but-paired peer with material impact;
MEDIUM = bounded abuse / defense-in-depth gap; LOW = hardening.

## Verified secure (checked, found sound)

- **Handshake & trust binding** — 4-message X25519 + Ed25519 mutual auth; `deviceId = SHA-256(pubkey)` is verified on every pin operation (`PinnedPeer.init`, `PairingCoordinator.kt:38-42`); pin compare is constant-time (`EngineEncoding.constantTimeEquals`, `PairingCoordinator.kt:111`); QR pairing proofs are ephemeral-bound (nonce + both public keys + epk), single-use, 120 s TTL (`PairingCoordinator.kt:218-262`); TOFU auto-pin is **disabled** on both production ends (`PersistentPinStore(allowAutoTofuOnUnknownPeer = false)`, `InMemoryPinStore(allowAutoTofuOnUnknownPeer = false)`).
- **Envelope authentication & replay** — every post-handshake control envelope is Ed25519-verified against the *pinned* peer key **before** the replay window mutates (anti window-poisoning; `EnvelopeSigner.kt:142-154`, `Ec0Session.receiveEvent:188-199`); replay window = 64-packet bitmask + strict monotonic seq + 300 s clock-skew gate (`EnvelopeModel.kt:172-215`); offline_flush inner envelopes are signature-verified per item before routing (`SessionEnvelopeProcessor.verifyOfflineBatch:160-170`).
- **AEAD framing** — ChaCha20-Poly1305 with sessionId‖frameType‖counter as AAD; receiver enforces *exact* expected-counter equality (`AeadFrameCodec.openFrame:167-193`), so **replaying any frame — including bulk file/clipboard chunks — is cryptographically impossible**; counter 0 reserved for AUTH_CONFIRM; rekey epoch chain fails loudly on gaps (`AeadSessionChannel.openRekeyNotice:335-388`).
- **Wire limits** — WS frame and reassembled-message caps enforced (`Ec0WsCodec.readFrame/readMessage:203-260`); unknown post-handshake AEAD frame types throw.
- **Beacon verification on receipt** — the audit question "are received beacons verified" is YES at the envelope layer: `presence_beacon` cannot reach `PresenceService.handleControlEnvelope` without passing signature + replay checks in `Ec0Session.receiveEvent`. A third party cannot spoof a peer's beacon. Remaining nuance (tracked via H1): capabilities are *self-asserted* by the authenticated peer, so they must gate surfaces on the *receiver*, which H1 now does for input.
- **Bulk stream integrity** — per-chunk SHA-256 (constant-time compare) + full-file SHA-256 before atomic rename; out-of-order and oversize chunks fail the transfer (`FileTransferService.handleBulkChunk:475-580`).
- **File-transfer path containment** — `sanitizeRelativePath` rejects absolute paths, backslashes, `:`/drive prefixes, control chars, `.`/`..` segments (`FileTransferModels.kt:238-263`), plus canonical-root prefix check (`FileTransferService.resolveSafeTargetFile:622-631`).
- **LocalSend receiver** — upload target containment (`target.startsWith(destination)`, `LocalsendReceiverKtor.kt:163-169`), declared-size overflow guard, token+IP session binding, checksum verification, PIN attempt rate limit → 429 (`LocalsendSecurity.evaluatePin`), ASK accept policy on both ends; `IncomingSessionStore` TTL sweep bounds session lifetime.
- **Handoff URL execution** — strict `http`/`https`-only validation with length + control-char regex (`HandoffAndProximityModels.kt:41-50`), re-validated at the model `init` and again at the exec site; all process launches are **argv-list (never shell)**: ydotool/xdotool (`LinuxInputInjectionBridge`), adb with serial regex `^[A-Za-z0-9._-]+$` (`Slice11ContinuityServices.kt:112-116,176`), busctl/playerctl targeting (`MprisDesktopMediaSource` — player ids come from local busctl enumeration, never from remote metadata; metadata is parsed as JSON and only displayed).
- **uinput setup** — `UinputSetupScript.script()` is a fixed string with no interpolation of remote data (no argv/path injection in device setup); hot path is plain `write()` of 24-byte evdev records.
- **Secrets at rest** — `identity.enc.json` (seed sealed with ChaCha20-Poly1305 under HKDF(master.key), AAD-bound to deviceId), `master.key`, `pinned_peers.json`, `daemon_ipc.json` all written 0600 via temp-file + atomic rename (`PersistentEngineStore.kt:180-205`); config dir forced 0700; Android uses `filesDir`-scoped stores. Code never relaxes these bits.
- **Log hygiene** — session/pairing/handshake logs emit aliases, deviceIds and exception classes only; no key material, signatures, tokens, or PINs in any log line reviewed (`Ec0EngineNode.kt:318-330`, `PairingCoordinator.kt:249-251`, `Ec0Server` handshake errors).
- **IPC daemon** — `LocalDaemonIpcServer` binds `127.0.0.1` on an ephemeral TCP port (not a world-connectable unix socket), auth token = 32 SecureRandom bytes persisted 0600, descriptor deleted on close; IPC path arguments only pre-select files for an explicit user-style send (token-gated).
- **Android exported components** — every `exported=true` service carries a system-held permission (`BIND_QUICK_SETTINGS_TILE` × 2, `BIND_NOTIFICATION_LISTENER_SERVICE`); `FindMyRingActivity` is `exported=false`; `MainActivity` is launcher-only. Tiles act only through in-process seams (`Ec0TileState`) — no exported IPC surface for peers.
- **Input sender path** — `RemoteInputScreen` batches ≤8 ms and every burst goes through `InputShareService.sendKeyEvent/sendPointerEvent → session.sendCmd` → signed envelope in the AEAD session; **no bypass path sends raw frames** (the only `sendRawWsFrame` callers are PING/PONG/CLOSE and the handshake itself).
- **Notification inline reply** — desktop `notif_reply` executes only against a *cached* PendingIntent captured from a real Android notification at post time (no arbitrary intent construction from remote data).

## Residual risks (accepted / documented)

1. ~~**M2** (Ec0Server handshake bound)~~ — **Resolved**: `Ec0Server` enforces `Semaphore(32)` around pre-auth handshakes.
2. ~~Desktop receiver-side capability grant enforcement~~ — **Resolved (S1 below)**.
3. Unpair completeness for **LocalSend fingerprints**: neither side stores a per-peer engine↔LocalSend mapping yet, so unpair cannot prune LAN-only LocalSend fingerprints automatically (engine pins and desktop `peer_grants.json` are both pruned immediately on 2-way unpair).
